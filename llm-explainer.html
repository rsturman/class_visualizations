Section 01 — The Big Picture

What is a Large Language Model?

An LLM is a computer program that has learned to understand and generate human language by studying enormous amounts of text. It doesn't look up answers in a database — it has compressed patterns from billions of documents into a vast web of numerical weights, and it uses those weights to predict what words should come next.

The four-phase life of a large language model
Collect
Billions of web pages, books, and code are gathered and cleaned.
Pre-Train
The model is taught to predict the next word — trillions of times.
Align
Human raters teach the model to be helpful, honest, and safe.
Deploy
The model is served via an API powering apps, chat, and agents.
The "large" refers to the number of parameters — the numerical dials inside the model that encode everything it has learned. Early models had millions. GPT-2 (2019) had 1.5 billion. Modern frontier models are estimated to have hundreds of billions or even trillions of parameters. More parameters means the model can store more nuanced patterns about language — but it also means far more compute and energy is required to train it.
A search engine finds existing documents. A database looks up stored facts. An LLM does something different: it has compressed statistical patterns from text into weights — it doesn't retrieve, it generates. This is why it can write poetry, explain concepts in new ways, or combine ideas it never saw together — but also why it can confidently produce plausible-sounding falsehoods.
Section 02 — Training

How the Model Learns

Training is the process of teaching the model by making it practice a simple task — predict the next word — billions of times. Each time it gets something wrong, it adjusts its internal weights slightly. Over trillions of examples, this simple task forces the model to develop deep understanding of language, facts, and reasoning.

The training loop — repeated billions of times to build the model's knowledge
The Two Training Phases
Pre-Training
The model reads virtually all of the internet, Wikipedia, books, and code — and practices next-word prediction on all of it. This is the most expensive phase. It builds broad world knowledge.
Fine-Tuning & RLHF
Human trainers provide example conversations and rate different responses. The model is updated to prefer helpful, honest, harmless replies. This shapes the "personality" of the assistant.
What it learns
Grammar, facts, reasoning patterns, coding syntax, style, tone — all encoded as numbers. No one programs these explicitly; they emerge from predicting text.
When the model makes a wrong prediction, we need to figure out which of its 100+ billion weights were responsible for the error, and how much to adjust each one. Backpropagation is the algorithm that does this efficiently — it traces the error backwards through the network using calculus (the chain rule), computing a small "blame" value for each weight. Then each weight is nudged by a tiny amount in the direction that would have reduced the error.
Reinforcement Learning from Human Feedback. After pre-training, human raters compare pairs of model responses ("which is better?"). Their preferences are used to train a separate reward model that scores responses. The LLM is then updated using RL to score higher on the reward model — essentially learning to produce responses humans find helpful and appropriate. This is how a raw text predictor becomes a helpful assistant.
Section 03 — Tokens & Embeddings

From Text to Numbers

Computers can only process numbers, not letters. Before any text reaches the model, it must be converted into a numerical form through two steps: tokenization (splitting text into chunks) and embedding (converting each chunk into a list of numbers that captures its meaning).

Text → Tokens → Vocabulary IDs → Embedding vectors
Vocabulary
Most LLMs use ~32,000–100,000 tokens. Common words are single tokens; rare words get split into sub-word pieces like Un + believ + able.
Context Window
The model can only "see" a limited number of tokens at once — its context window. Older models: 2,048 tokens. Modern models: 128,000–1,000,000+ tokens.
Embedding Space
Embeddings place tokens in a high-dimensional geometric space. Words with similar meanings end up near each other — meaning is encoded in position.
Using individual characters would require the model to learn spelling from scratch and would make sequences very long — inefficient. Using whole words would make the vocabulary too large and fail on unknown words like new names or neologisms. Sub-word tokenization (the BPE or WordPiece approach) is the sweet spot: common words get their own token, rare words are split into familiar pieces. "ChatGPT" might be Chat + G + PT.
Section 04 — The Transformer Architecture

Inside the Neural Network

The "transformer" is the neural network architecture that powers all modern LLMs. It processes all tokens at once (not one by one) and uses a mechanism called attention to figure out which tokens are most relevant to each other — allowing it to understand long-range relationships in text.

The Transformer block — stacked 32–128 times in large models
Self-Attention
Every token computes how much it should "attend to" every other token. This allows the model to resolve references ("it" → "animal") across any distance.
Feed-Forward
After attention, each token passes through a small neural network that applies further transformations — this is where most factual knowledge is thought to be stored.
Stacking Blocks
Stacking 32–128 identical blocks lets the model build increasingly abstract representations — from letters, to words, to concepts, to reasoning.
Before Transformers (introduced in the 2017 paper "Attention Is All You Need"), language models processed text sequentially — one word at a time. This was slow and made it hard to connect words that were far apart in a sentence. The Transformer processes all tokens simultaneously and lets every token directly attend to every other token, no matter the distance. This made training far faster (parallelizable on GPUs) and allowed models to handle much longer contexts with far better comprehension.
Section 05 — Generating Text

How the Model Writes

Once trained, the model generates text one token at a time. For each new token, it runs a forward pass through all its layers, producing a probability distribution over its entire vocabulary. It samples from that distribution — then appends the chosen token and repeats until done.

The autoregressive generation loop — one token at a time
Temperature: Controlling Creativity

The temperature parameter controls how the model samples from its probability distribution. At low temperatures, the model almost always picks the most likely token — safe but predictable. At high temperatures, it spreads probability more evenly, producing more surprising (sometimes incoherent) results.

Hallucination is when a model generates confident-sounding but false information. It happens because the model is a pattern completer, not a fact retrieval system. When a question has a likely-sounding continuation in its training data — even if that continuation is wrong — the model may generate it. It has no internal "truth checker." The model doesn't know what it doesn't know, so it fills gaps with plausible-sounding text. This is why LLM outputs should always be verified for high-stakes factual claims.
Section 06 — Chat & Agents

From Model to Product

A raw LLM is just a next-token predictor. To build a useful assistant or agent, developers wrap it in a conversation structure, give it access to tools, and let it reason in loops — repeatedly thinking, acting, and observing until a task is complete.

The Chat Stack
How a chat turn works — system prompt + history + new message = model input
AI Agents

An agent is an LLM that can take actions — call tools, browse the web, write and run code, send emails — and then observe the results to decide what to do next. Rather than answering in one shot, it runs a loop: think → act → observe → think → act… until the task is complete.

The agent loop — think, use a tool, observe the result, repeat
System Prompt
A hidden instruction that shapes the model's behavior — its persona, constraints, and available tools. Users typically don't see it.
Tools
Functions the model can call: web search, code execution, file reading, database queries, sending emails. The model decides when and how to call them.
Memory
LLMs have no built-in long-term memory. Context window = working memory. Agents use external databases (RAG) to retrieve relevant past information.
RAG is a technique for giving an LLM access to specific knowledge it wasn't trained on — like a company's private documents. When a user asks a question, a search system first retrieves the most relevant chunks of text from a database, then stuffs them into the context window alongside the user's query. The model then answers based on the retrieved content rather than (only) its trained weights. This reduces hallucination and keeps the model's knowledge up to date without retraining.
Despite impressive capabilities, LLMs have significant limits today: Hallucination — they generate confident falsehoods. Context window — they can only process so much text at once. Reasoning — they can fail on multi-step logical problems despite appearing capable. Recency — training data has a cutoff date. World interaction — agents still struggle with reliable, long-horizon task completion. Cost — large models are expensive to run at scale. Research in all these areas is extremely active.
